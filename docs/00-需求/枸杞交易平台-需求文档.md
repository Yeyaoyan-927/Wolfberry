## 0. 版本变更说明（v3.0 → v4.0）

前三个版本对产品形态判断有误，本版回到正确方向并合并已有成果。

| 版本 | 当时的理解 | 问题 |
|---|---|---|
| v1.0 | 枸杞交易平台 + 知识问答 | 方向正确，但把"检测"当成了知识问答，未落到图像能力；且误用了"房源"模板词 |
| v2.0 | 收购点现场多模态筛查工具（图像 + 光谱） | 偏离交易平台，硬加光谱硬件 |
| v3.0 | 仅图像外观筛查工具（单机、无 Docker、CPU） | 业务形态仍是"质检工具"，不是"买卖平台" |
| **v4.0** | **枸杞交易平台**：卖家上传、平台审核、买家下单 | 本版 |

**本版保留与复用**

| 来源 | 复用内容 |
|---|---|
| v1.0 | 双端结构、买卖场景、行情分析、RAG 与 LangGraph 技术架构、MySQL 建模方法、接口规范 |
| v3.0 | YOLO 图像外观评估（CPU/ONNX）、两级图片门禁、多图汇总算法、置信度分级、仅外观不承诺内部品质的边界 |
| 原技术要求 | Vue 3 + Element Plus、FastAPI、MySQL、RAG、Agent、LangChain、LangGraph 全部落点保留 |

**本版关键新增**

1. **商品发布 → AI 评估 → 人工审核** 的完整审核链路（平台的核心治理机制）。
2. **"卖家自述等级 vs AI 建议等级"差异标记**（防止高报等级、图文不符）。
3. 交易闭环（下单 → 确认 → 发货 → 收货）、评价、售后纠纷。
4. 基于**平台成交数据**的行情分析（含冷启动方案）。
5. 卖家资质准入与商品图文一致性校验（盗图检测）。

## 1. 产品定位与核心逻辑

### 1.1 一句话定位

> 一个枸杞 B2B/B2C 交易平台：卖家上传实拍图发布货源，平台用 AI 做外观评估后人工审核上架，买家看图看数据下单，全程留痕可追溯。

### 1.2 要解决的核心问题

| 问题 | 现状 | 平台解法 |
|---|---|---|
| **图文不符** | 卖家写"特级"，实际是甲级甚至等外；买家收到货才发现 | AI 图像评估给出客观外观指标，与卖家自述等级比对，差异超标直接拦在审核环节 |
| **等级无标准** | 各家口径不一，"特级"含义不同 | 统一按 GB/T 18672 外观维度映射到平台等级，评估结果公开可查 |
| **比价成本高** | 靠微信/电话一问一价，无法横向比较 | 结构化商品字段（品种/产区/规格/等级/报价）+ 行情看板 |
| **决策缺依据** | 不懂标准、不懂行情 | 智能问答：标准条款、等级判定、行情走势，均带数据来源 |
| **纠纷无证据** | 各说各话 | 审核时的 AI 评估记录 + 原图存档，作为纠纷判定依据 |

### 1.3 AI 图像评估在平台中的三重价值

| 场景 | 作用 | 说明 |
|---|---|---|
| ① 审核依据 | 审核员看到 AI 外观指标与建议等级，不用凭肉眼比对 | 缩短审核时长，统一审核尺度 |
| ② 商品公信力 | 商品页展示"平台 AI 外观评估"卡片 | 买家看到客观数值，不只信卖家描述 |
| ③ 纠纷证据 | 售后争议时调取上架时评估快照 | 判断是否"上架时就与描述不符" |

> **AI 不替代审核员**：AI 只给指标与建议，最终是否上架、定什么等级，由审核员决定并签字留痕。

### 1.4 三方价值

| 角色 | 得到什么 |
|---|---|
| 买家 | 看得见的客观指标、可比的报价、可查的行情、可问的智能助手 |
| 卖家 | 免费的外观质检（减少因描述不符被退货）、审核通过的等级成为背书、曝光与成交 |
| 平台 | 商品质量可控、纠纷可裁、数据资产（成交价、产区、等级分布）沉淀 |

### 1.5 边界

**做**：商品发布与审核、图像外观评估、报价与下单、订单流转、评价与售后、行情分析、智能问答、后台治理。

**不做**：
- 在线支付与资金托管（订单记录金额，支付线下完成，仅登记状态与凭证）。
- 物流轨迹对接（只记录物流公司与单号）。
- 实验室理化检测（硫、水分、多糖、农残、重金属）—— 平台不出检测报告，仅要求卖家上传第三方报告作为附件（可选）。
- 自动定价、自动分级上架（等级必须人工确认）。
- 自营采购、仓储、代发。

## 2. 角色与权限

### 2.1 角色

| 角色 | 端 | 说明 | 核心权限 |
|---|---|---|---|
| 买家 | 交易端 | 采购枸杞（商超、批发商、餐饮、个人） | 浏览、搜索、比价、问答、下单、评价、售后 |
| 卖家 | 交易端 | 合作社、种植大户、加工厂、贸易商 | 发布/编辑商品、上传图片、查看 AI 评估、处理订单、发货 |
| 审核员 | 后台 | 商品审核（核心岗位） | 查看待审商品、AI 评估、通过/驳回/改级、要求补充材料 |
| 运营 | 后台 | 订单干预、售后仲裁、活动与内容 | 订单查询与干预、售后处理、行情数据维护 |
| 知识库管理员 | 后台 | 维护问答知识 | 文档上传、分块、召回测试 |
| 系统管理员 | 后台 | 账号、权限、模型、配置 | 全部后台功能（不含改结论） |
| 财务（可选） | 后台 | 对账 | 订单金额查询、导出、支付状态登记 |

> 审核员与卖家**不得为同一人**；审核员不得审核自己关联企业发布的商品（系统校验 `seller_id` 与审核员所属组织）。

### 2.3 卖家准入（必须先过资质才能发布）

| 项 | 要求 | 审核方 |
|---|---|---|
| 实名认证 | 身份证 + 人脸核验（或对公打款验证） | 系统自动 + 人工抽检 |
| 主体类型 | 个人 / 合作社 / 企业 | 人工 |
| 营业执照 | 企业/合作社必传，需在有效期 | 人工 |
| 产地证明 | 可选（有则加"产地认证"标） | 人工 |
| 经营类目 | 干果类 | 系统 |
| 保证金 | 本期不做（预留字段） | — |

**状态机**：`待提交 → 待审核 → 已通过 / 已驳回（可重提）→ 已冻结（违规）`。未通过资质审核的账号，发布入口置灰并提示。

## 3. 核心业务流程

### 3.1 商品发布与审核（平台核心链路）

```
 ┌──────────┐   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
 │ 卖家填写  │──▶│ 上传实拍图    │──▶│ 提交审核      │──▶│ AI 外观评估   │
 │ 商品信息  │   │ 3~8 张       │   │ 状态=待审核   │   │ 自动触发      │
 │ 自述等级  │   │ L1 门禁      │   │              │   │ 30s 内出结果  │
 └──────────┘   └──────────────┘   └──────────────┘   └──────┬───────┘
                                                              │
                                    ┌─────────────────────────┘
                                    ▼
                        ┌────────────────────────┐
                        │ 生成审核任务（进入队列） │
                        │ 含：AI指标 + 建议等级    │
                        │ + 差异标记（自述 vs AI） │
                        └───────────┬────────────┘
                                    ▼
                        ┌────────────────────────┐
                        │ 审核员工作台             │
                        │ 左：商品信息与自述        │
                        │ 中：图片 + AI 标注图      │
                        │ 右：AI评估 + 差异标记     │
                        └───┬────────┬───────┬────┘
                            │        │       │
                        通过│    驳回│   改级通过│
                            ▼        ▼       ▼
                     ┌──────────┐ ┌──────┐ ┌──────────┐
                     │ 上架     │ │退回  │ │ 按审核员  │
                     │ 展示AI卡 │ │卖家  │ │ 等级上架  │
                     └──────────┘ └──────┘ └──────────┘
```

**时效要求**：卖家提交后 **4 小时内**（工作时段 9:00-18:00）必须出审核结论；超时自动提醒并计入运营看板。

**提交前置校验（自动拦截，不进人工）**

| 校验 | 规则 | 不通过 |
|---|---|---|
| 必填完整性 | 品种、产区、规格、等级、报价、库存、起订量、发货地 | 表单标红 |
| 图片数量 | 3~8 张，含至少 1 张全貌 | 拒绝提交 |
| 图片质量 | L1 门禁（格式/大小/短边/模糊/曝光） | 拒绝该图 |
| 图片去重 | 与自己历史商品 pHash 相似度 > 0.95 | 提示"该图已用于其他商品" |
| 盗图检测 | 与平台在架商品图 pHash 相似度 > 0.92 | **直接拒绝**，记违规 |
| 价格合理性 | 偏离同品类近 30 天均价 ±60% | 提示确认（不阻止） |
| 库存 | > 0 | 拒绝 |

### 3.2 交易流程

```
买家下单 ──▶ 库存冻结 ──▶ 待卖家确认 ──┬─▶ 卖家确认 ──▶ 待发货 ──▶ 已发货 ──▶ 确认收货 ──▶ 已完成
   │                                  │                                              │
   │                                  └─▶ 卖家拒单/超时24h ──▶ 已取消（释放库存）      ▼
   └─▶ 买家取消（待确认阶段可取消）                                  ┌──────────────┐
                                                                    │ 评价（买家）  │
                                                                    │ 售后（15天内）│
                                                                    └──────────────┘
```

**规则**

- 下单即冻结库存（`stock_frozen`），取消/拒单释放；确认后转为已售。
- 卖家 24 小时未确认，系统自动取消并通知双方。
- 支付线下：订单记录 `pay_status`（未付/已付/部分付）与凭证图片（可选上传）。
- 发货必填物流公司 + 单号；不做轨迹对接。
- 收货后 15 天内可申请售后，超期关闭入口。

### 3.3 售后与纠纷

| 类型 | 触发 | 处理 |
|---|---|---|
| 图文不符 | 买家举证（实拍图 vs 商品图） | 平台调取**上架时 AI 评估快照**与审核记录，对比判断 |
| 质量问题（霉变/杂质） | 买家上传照片 | 优先换货/退款，责任方由平台判定 |
| 少货/错货 | 买家举证 | 补发或退款 |
| 物流破损 | 双方举证 | 卖家承担（未保价按约定） |

流程：`买家申请 → 卖家响应（48h）→ 平台仲裁（运营）→ 执行（退款/退货/驳回）→ 关闭`。仲裁必须写明依据并留痕。

### 3.4 状态机

**商品 `product.status`**

```
草稿(0) → 待审核(1) → 审核中(2) → 已上架(3) → 已下架(5)
              │            │
              │            ├→ 已驳回(4)（可编辑后重提）
              └────────────┴→ 违规下架(6)
支付... （无）
```

**订单 `order.status`**

```
待确认(1) → 待发货(2) → 已发货(3) → 已完成(4)
   │            │
   └→ 已取消(5) └→ 售后中(6) → 已关闭(7)
```

## 4. 功能需求

### 4.1 交易端 — 买家

**FR-B-01 商品浏览与搜索（P0）**

- 首页：分类入口、今日行情卡、推荐商品、产地专区。
- 列表页筛选：品种、等级、产区、规格（粒/50g）、价格区间、起订量、是否有 AI 评估、卖家类型、是否有现货。
- 排序：综合、价格升降、最新上架、AI 评估缺陷率升序（"越靠前越干净"）、销量。
- 搜索：关键词（标题/品种/产区）+ 筛选条件叠加；支持"只搜有 AI 评估的商品"。
- 验收：20 万商品下筛选列表 P95 ≤ 500ms；筛选条件可分享（URL 参数同步）。

**FR-B-02 商品详情（P0）**

| 区块 | 内容 |
|---|---|
| 图片区 | 主图 + 缩略图（含 AI 标注图 Tab：可切换"原图/标注图"）；图片水印（防盗） |
| 核心信息 | 标题、平台等级（审核确认）、卖家自述等级、品种、产区、规格、含水率（卖家自述）、库存、报价、起订量、发货地 |
| **AI 外观评估卡** | 粒数区间、坏果率、霉变率、油果率、杂质率、相对粒径、评估时间、`仅外观维度，不含理化指标` 角标 |
| 卖家信息 | 店铺名、资质标（企业/合作社/产地认证）、评分、历史成交、响应时长 |
| 交易 | 数量选择（≥起订量）、立即下单、加入询价（可选 P2） |
| 保障 | 平台审核标、图文一致承诺、售后规则 |
| 问答入口 | "问AI"按钮，带入当前商品上下文提问 |

- 验收：详情页首屏 ≤ 800ms；标注图切换 ≤ 300ms。

**FR-B-03 智能问答（P0）**

- 入口：全局悬浮按钮 + 商品详情页"问AI"（自动带入商品上下文）。
- 能力：标准条款（GB/T 18672 等级怎么分）、行情（近半年中宁宁杞5号价格走势）、选品建议（预算内性价比高的货源）、平台规则（怎么退货）。
- 必须引用来源：标准给条款号、行情给数据表与统计口径、商品给商品 ID。
- 无依据时明确"知识库未收录"，禁止编造。
- 验收：引用准确率 ≥ 95%；无据作答 ≤ 3%；首 Token P95 ≤ 2.5s。

**FR-B-04 下单（P0）**

- 校验：数量 ≥ 起订量、≤ 可用库存、商品在架、卖家资质有效。
- 下单页展示：商品快照（标题/规格/等级/单价）、数量、金额、运费说明（卖家承担/买家承担/到付）、收货信息、备注。
- 提交后：冻结库存、生成订单号、通知卖家。
- 幂等：`client_order_id` 防重复提交。
- 验收：下单 ≤ 500ms；并发下单不超卖（`UPDATE ... WHERE stock_frozen + qty <= stock`）。

**FR-B-05 我的订单（P0）**

- 列表按状态分 Tab；详情含状态时间线、物流信息、金额明细、操作按钮（取消/确认收货/申请售后/评价）。
- 验收：状态变更后 5s 内可见（轮询或消息推送）。

**FR-B-06 评价（P1）**

- 收货后可评：商品符合度（1-5）、描述一致性（1-5）、发货速度（1-5）、文字、图片。
- 影响卖家评分（加权计算，规则见 4.5）。
- 同一订单仅一次评价，7 天内可修改一次。

**FR-B-07 售后申请（P1）**

- 类型：图文不符 / 质量 / 少货 / 物流破损 / 其他。
- 必填：问题描述、举证图片（≥1 张）、诉求（退款/换货/补发）。
- 提交后进入售后流程，可查看进度与平台裁定。

### 4.2 交易端 — 卖家

**FR-S-01 卖家中心（P0）**

- 首页：待审核数、在架数、待发货订单、本月成交额、AI 评估平均缺陷率、被驳回原因 Top3。
- 快捷入口：发布商品、处理订单、查看评估。

**FR-S-02 发布商品（P0，核心）**

分步表单：

| 步 | 字段 |
|---|---|
| 1 基本信息 | 标题（≤60 字）、品种、产区（省/市/县）、采摘年份、规格（粒/50g）、**自述等级**、含水率（自述） |
| 2 交易信息 | 单价（元/kg）、库存（kg）、起订量（kg）、发货地、运费承担方、发货时效（小时） |
| 3 图片上传 | 3~8 张：全貌 ≥1 张（必填）、细节 ≥2 张、包装/标签（可选）；上传后逐张显示 L1 门禁结果 |
| 4 描述与资质 | 商品描述（≤1000 字）、可选上传第三方检测报告（PDF/图片）、产地证明 |
| 5 提交 | 预览 + 提交审核 |

- **预检功能（P1）**：卖家可在正式提交前点"先测一下"，仅跑 AI 评估不进入审核队列，看到建议等级后再决定是否提交（避免被驳回）。预检结果不下架、不公开，保留 7 天。
- 必填项未填不可提交；图片不足 3 张不可提交。
- 验收：发布页加载 ≤ 1s；图片上传单张 ≤ 3s（10MB）；提交 ≤ 500ms。

**FR-S-03 我的商品（P0）**

- 列表：状态、平台等级、自述等级、AI 建议等级、报价、库存、曝光、下单数。
- 操作：编辑（仅草稿/驳回/已下架状态）、重新提交、下架、复制发布。
- **已上架商品修改图片或等级需重新审核**（防止上架后换图）。
- 验收：编辑后状态自动置"待审核"，原版本保留为历史。

**FR-S-04 查看 AI 评估（P0）**

- 展示：外观指标、标注图、建议等级、与自述等级的差异、驳回原因（若被驳回）。
- 若对结果有异议：可提交"申诉"（附说明），流转至运营复核（限 1 次/商品）。
- 验收：评估结果页 ≤ 800ms。

**FR-S-05 订单处理（P0）**

- 待确认订单：确认 / 拒单（必填原因）。
- 待发货：填写物流公司 + 单号 → 发货。
- 售后：48 小时内响应（同意/拒绝 + 理由）。
- 验收：操作 ≤ 300ms；超时未处理自动提醒（站内信 + 列表红标）。

**FR-S-06 店铺与资质（P1）**

- 店铺信息、资质上传与状态、评分明细、违规记录。

### 4.3 后台 — 商品审核（核心工作台）

**FR-A-01 审核队列（P0）**

- 默认按"提交时间升序"（先到先审），支持按"风险优先"（红标优先）切换。
- 列表字段：商品缩略图、标题、卖家、自述等级、**AI 建议等级**、差异标记、提交时间、等待时长。
- 超 4 小时未处理标红；超 8 小时告警运营。
- 验收：队列加载 ≤ 500ms；支持键盘 ↑↓ 切换。

**FR-A-02 审核详情工作台（P0）**

三栏布局：

| 栏 | 内容 |
|---|---|
| 左（360px） | 商品全部字段、卖家资质、历史违规、历史驳回原因、同类商品行情参考价 |
| 中（自适应） | 图片网格（原图/标注图切换、放大、逐张查看）；L1/L2 门禁结果；盗图比对结果 |
| 右（400px） | **AI 评估卡**（指标 + 建议等级 + 置信度）、**差异标记**、审核操作区 |

**审核操作**

| 操作 | 说明 | 后续 |
|---|---|---|
| 通过（原等级） | 认可卖家自述等级 | 上架 |
| 通过（调整等级） | 改为审核员认定等级（可高于或低于自述） | 上架，记录改级原因 |
| 驳回 | 必填原因（枚举 + 补充说明） | 退回卖家，可编辑重提 |
| 要求补充材料 | 指定材料（更清晰图片/检测报告/产地证明） | 卖家补充后重新进入队列 |
| 标记违规 | 虚假描述/盗图/违禁品 | 商品下架 + 记违规 + 可冻结账号 |

- 所有操作必须留痕：`product_audit` 记录审核员、操作、改前改后等级、原因、耗时。
- 快捷键：`A` 通过、`R` 驳回、`E` 改级、`→` 下一条。
- 验收：单商品审核平均耗时 ≤ 90 秒；操作 ≤ 300ms。

**FR-A-03 差异标记规则（防高报）**

| 卖家自述 | AI 建议 | 差异 | 标记 | 审核提示 |
|---|---|---|---|---|
| 与 AI 一致 | 同级 | 0 | 绿 | 常规核对即可 |
| 高报 1 级 | 低 1 级 | +1 | 黄 | "自述偏高，请重点核对缺陷率与粒数" |
| 高报 ≥2 级 | 低 ≥2 级 | ≥+2 | **红** | "自述明显偏高，建议驳回或改级"（默认聚焦驳回按钮） |
| 低报 | 高 ≥1 级 | ≤-1 | 蓝 | "自述偏低，可提示卖家上调"（不影响通过） |
| AI 置信度 < 0.45 | — | — | 灰 | "AI 评估不可靠，请人工判断"，不参与差异判定 |

> 红标商品在队列中排序靠前；同一卖家 30 天内红标 ≥ 3 次，触发账号预警。

**FR-A-04 商品管理（P1）**

- 全量商品检索、强制下架、批量下架、修改类目、查看历史版本（含图片与评估快照）。

**FR-A-05 审核统计（P1）**

- 审核量、平均时长、通过率、驳回原因分布、改级率、各审核员工作量与一致性（同一商品双人复核抽样）。

## 5. AI 图像评估设计（审核依据）

### 5.1 定位与边界

| 项 | 内容 |
|---|---|
| 目的 | 为审核提供客观外观指标，识别"图文不符" |
| 输入 | 卖家上传的 3~8 张实拍图 |
| 输出 | 外观指标 + **建议等级** + 置信度 + 标注图 |
| 不输出 | 硫、水分、多糖、农残、重金属等理化指标 |
| 不替代 | 人工审核（最终等级由审核员确认）、实验室检测 |
| 触发 | 提交审核时自动；卖家可主动预检 |

### 5.2 指标体系（仅外观）

| 指标 | 说明 | 单位 |
|---|---|---|
| 粒数 | 各图识别粒数汇总 | 粒 |
| 坏果率 | 破损、虫蛀、严重变形占比 | % |
| 霉变率 | 霉斑、发黑、霉味不可见但外观可辨的占比 | % |
| 油果率 | 变色、油浸、暗褐占比 | % |
| 杂质率 | 叶、梗、土、绳头等占比 | % |
| 相对粒径 | 以样品中位数为 100 的归一化指数（**不给 mm**，无标定） | 指数 |
| 颜色均匀度 | 色彩分布一致性（0-1） | — |
| 综合缺陷率 | (坏果+霉变+油果) / 总粒数 | % |

### 5.3 建议等级映射（规则引擎，非模型直接输出）

平台等级：`特优 / 特级 / 甲级 / 乙级 / 等外`，映射依据 GB/T 18672 的**外观相关维度**，理化指标不在范围内。

| 等级 | 综合缺陷率 | 霉变率 | 相对粒径中位数 | 说明 |
|---|---|---|---|---|
| 特优 | ≤ 1.0% | 0 | ≥ 108 | 果形均匀、无霉变、杂质极少 |
| 特级 | ≤ 2.0% | ≤ 0.2% | 100~108 | 少量坏果，无明显霉变 |
| 甲级 | ≤ 5.0% | ≤ 0.5% | 92~100 | 有可见缺陷但不影响整体 |
| 乙级 | ≤ 10.0% | ≤ 1.5% | 80~92 | 缺陷较明显 |
| 等外 | > 10.0% 或 霉变 > 1.5% | — | < 80 | 建议不予上架或按"处理品"标注 |

> **任一项不达则该等级不成立**（取最差项定级）。阈值全部可配（`grade_threshold_config`），且按版本快照。
> **霉变为一票否决项**：霉变率 > 1.5% 直接判等外，不允许上架（食品安全底线）。

### 5.4 置信度与人工兜底

| 样品置信度 | 处置 |
|---|---|
| ≥ 0.65 | AI 建议等级正常参与差异判定 |
| 0.45~0.65 | 标记"AI 评估偏低置信"，差异判定降级为提示，不作为驳回依据 |
| < 0.45 | **不参与判定**，审核员纯人工判断，记录"AI 未采信" |

低置信常见原因：图片模糊、堆叠严重、光照不均、混批。系统须在审核页显示原因，便于要求卖家补拍。

### 5.5 图片真实性与防作弊

| 手段 | 规则 | 处理 |
|---|---|---|
| 完全重复 | MD5 相同 | 拒绝（与自己或他人商品重复） |
| 近似重复 | pHash 汉明距离 ≤ 5（相似度 > 0.92） | 与他人商品重复 → 拒绝并记违规；与自己商品重复 → 警告 |
| 盗图库 | 平台在架图库 pHash 索引 | 命中即拒绝 |
| EXIF 校验 | 拍摄时间、设备型号 | 缺失或异常 → 标记"无原始信息"，不拒绝但提示审核员 |
| 截图识别 | 检测是否为屏幕截图（边框/摩尔纹） | 标记提示 |
| 图片数量 | 全貌 ≥1、细节 ≥2 | 不足拒绝提交 |

### 5.6 评估结果在商品页的展示

```
┌─────────────────────────────────────────────┐
│ 平台 AI 外观评估          [仅外观维度] ⓘ     │
├─────────────────────────────────────────────┤
│ 识别粒数    742 粒        样本图 4 张        │
│ 坏果率      3.1%          霉变率   0.1%      │
│ 油果率      1.2%          杂质率   0.3%      │
│ 综合缺陷率  4.4%          相对粒径 中偏大     │
│ 评估等级    甲级（与卖家自述一致）            │
│ 评估时间    2026-10-20 14:32                 │
├─────────────────────────────────────────────┤
│ 本评估基于卖家上传照片，仅反映外观特征，      │
│ 不含水分、多糖、硫残留等理化指标；            │
│ 结果供参考，以实物为准。                     │
└─────────────────────────────────────────────┘
```

> 买家侧**只展示审核确认后的最终等级**（平台等级），AI 建议等级仅在"与自述一致"时可视；不一致时仅展示最终等级，避免混淆。

### 5.7 技术实现（沿用 v3.0 已验证方案）

| 项 | 方案 |
|---|---|
| 模型 | YOLOv8n-seg / YOLOv8s-seg → ONNX |
| 推理 | ONNX Runtime CPU（短边 1024 降采样）；若主机有独显则自动切换 CUDA EP |
| 并发 | 单 worker 串行，队列消费；评估与浏览接口隔离，不互相拖慢 |
| 耗时 | 3~5 图约 8~15s；审核链路异步，不阻塞卖家提交 |
| 门禁 | L1 上传时规则校验；L2 模型跑完校验（粒数 20~500、遮挡 ≤40%、图级置信 ≥0.35） |
| 多图汇总 | 先合并计数再算比率，禁止对各图比率取平均；类别互斥优先级 霉变>坏果>油果>杂质>正常 |
| 存储 | 原图 + 降采样图 + 标注掩码；原图保留 1 年（可配），评估快照永久（纠纷举证需要） |

## 6. RAG 数据链路

### 6.1 知识范围

| 类别 | 内容 | 用途 |
|---|---|---|
| 国家标准 | GB/T 18672《枸杞》分级与外观术语 | 等级解释、术语问答 |
| 品种与产区 | 宁杞系列、大麻叶；中宁、诺木洪、精河、靖远等产区特点 | 选品建议 |
| 储存养护 | 防潮、防虫、避光、保质期 | 买家咨询 |
| 平台规则 | 交易流程、售后政策、审核标准、违规处理 | 规则问答 |
| 检测常识 | 硫、水分、多糖为什么要测（**只讲概念，不给数值判定**） | 解释为什么平台不测 |
| 行情方法 | 价格指数的统计口径、样本说明 | 行情解读 |

> **结构化数据不入向量库**：商品、价格、订单、评估结果全部走 SQL 工具查询。

### 6.2 入库链路

```
上传 → 解析 → 清洗 → 切分 → 元数据标注 → 向量化 → 索引 → 抽检
       │      │      │        │            │        │
   PDF/DOCX  去噪  条款级   标准号/条款/页码  bge-m3   faiss+MySQL
```

| 步骤 | 处理 | 失败处理 |
|---|---|---|
| 解析 | pypdf / python-docx；表格转 Markdown；保留页码与标题层级 | 扫描件无文本层 → 拒绝并提示需 OCR |
| 清洗 | 去页眉页脚、水印、统一全半角、修复断行 | 清洗后字符 < 原文 30% 告警 |
| 切分 | 标准按条款（500 字/重叠 80）；FAQ 按问答对；报告按段落（600 字/重叠 100） | 超长块二次切分 |
| 标注 | 标准号、条款号、页码、生效日期、适用范围 | 缺页码置空 |
| 向量化 | bge-m3（1024 维），批量 16 条，失败重试 3 次 | 单批失败降级逐条 |
| 索引 | 写 `kb_chunk` + 更新 faiss | 索引损坏一键重建 |

**上下文前缀**：每块入库前拼接 `【标准号｜文档标题｜条款号｜页码｜生效日期】`，显著降低条款错配。

### 6.3 召回与重排

| 环节 | 设计 |
|---|---|
| 向量召回 | bge-m3 + faiss（余弦），TopK=20 |
| 关键词召回 | MySQL FULLTEXT（ngram），匹配标准号、指标名，TopK=20 |
| 元数据过滤 | 分类、文档类型、生效日期、状态 |
| 融合 | RRF（`Σ 1/(60+rank)`），取 Top12 |
| 重排 | gte-rerank，Top5；`θ_high=0.55` 可答，`θ_low=0.30` 声明不确定，`<θ_low` 判"未收录" |
| 降级 | 重排超时按融合分排序；向量不可用退化为关键词 |

### 6.4 引用溯源

- 生成时给上下文编号 `[1]..[5]`，要求每条结论带编号。
- 生成后校验：编号必须存在；含数值/结论的句子无编号 → 判 `ungrounded`，重写 1 次，仍不合格则降级为"未找到依据"。
- 引用卡片：标准号 / 文档名 / 条款号 / 页码 / 原文片段（≤200 字），点击打开抽屉并高亮。
- 数据类回答附结构化来源：表名、筛选条件、行数、统计口径、生成时间。

### 6.5 评测

| 指标 | 目标 |
|---|---|
| Recall@5 | ≥ 0.85 |
| MRR | ≥ 0.70 |
| 引用准确率 | ≥ 95% |
| 无据作答率 | ≤ 3% |
| 拒答正确率（知识库外问题） | ≥ 90% |

## 7. LangGraph Agent 编排

### 7.1 设计原则

1. 图优先于链：需要分支、循环、并行的一律用 LangGraph 显式表达。
2. 单一职责节点：每节点只做一件事，输入输出落在 State，便于单测与回放。
3. 确定性优先：等级映射、价格计算、格式校验用规则，不交给 LLM。
4. 有界执行：工具 ≤ 6 次、自检 ≤ 2 次、单请求 ≤ 25s。
5. 全程留痕：每节点写 `agent_trace`。

### 7.2 State

| 字段 | 说明 |
|---|---|
| `session_id` / `trace_id` / `user_id` / `role` | 标识与身份（role 决定可用工具与数据范围） |
| `messages` | LangChain 消息序列（最近 6 轮 + 摘要） |
| `user_input` / `normalized_query` | 原始与清洗后输入 |
| `intent` | `knowledge_qa` / `market_price` / `product_search` / `product_detail` / `grade_explain` / `order_intent` / `rule_qa` / `chitchat` / `out_of_scope` |
| `intent_confidence` | < 0.6 触发澄清 |
| `slots` | 品种、产区、等级、规格、价格区间、时间范围、数量、订单号、商品 ID |
| `rewritten_queries` | 1~3 条检索式 |
| `retrieval` | 向量/关键词/融合/重排结果与最高分 |
| `plan` / `step_index` | 子任务计划 |
| `tool_results` / `structured_data` | 工具返回与结构化数据（含 chart_option） |
| `citations` | 引用列表 |
| `draft_answer` / `self_check` | 草稿与自检结果 |
| `memory` | 会话摘要 + 用户偏好（常用品种、产区、采购量级） |
| `error` / `next` | 错误与路由 |

### 7.3 图结构

```
                    ┌────────────┐
        START ─────▶│ n0 guard   │ 长度/敏感词/越界/注入检测
```

### 7.6 记忆与状态

| 层 | 存储 | 内容 | 生命周期 |
|---|---|---|---|
| 短期 | State（内存） | 本轮中间结果 | 单请求 |

### 7.7 异常兜底

| 异常 | 处理 | 用户可见 |
|---|---|---|
| 模型超时（>12s） | 重试 1 次（换轻量模型）→ 输出已生成片段 | "回答生成中断，已保留部分内容，点击重试" |
| 模型限流 429 | 退避重试 3 次 → 降级模型 → 排队 | "当前咨询较多，请稍候" |
| 向量服务不可用 | 退化为关键词检索 | 附"检索能力降级"提示 |
| 召回为空 | n12：给可执行建议 + 推荐相似问题 | "暂未找到相关资料，你可以…" |
| 意图不清 | n12：二选一澄清 | "你想了解行情价格，还是找货源？" |
| 槽位缺失 | 追问最多 2 个必填项 | "请补充目标产区或价格区间" |
| 工具空集 | 不报错，标 `empty=true` | "当前筛选无匹配，已放宽到…" |
| 工具报错 | 重试 1 次 → 换备选工具 | 部分结果 + "部分数据获取失败" |
| 越权查他人订单 | 拒绝并记安全日志，不暴露存在性 | "未查询到该订单" |
| 提示词注入 | 拦截，原文记安全审计 | "该问题不在服务范围内" |
| 全链路 25s | 强制结束，输出已完成部分 | "分析超时，已返回部分结果" |

## 9. MySQL 数据模型

### 9.1 约定

- InnoDB / utf8mb4 / `utf8mb4_0900_ai_ci`；主键 `BIGINT UNSIGNED`。
- 金额 `DECIMAL(12,2)`，比率 `DECIMAL(6,4)`，数量 `DECIMAL(12,3)`；禁浮点存金额。

### 11.4 关键交互

**卖家发布商品（5 步）**

- 顶部步骤条，可回退到已填步骤，不可跳过。
- 第 3 步上传：拖拽/多选/Ctrl+V；每张上传后立即显示 L1 徽标与失败原因；支持"设为全貌图"。
- 第 5 步预览：展示"买家将看到的样子"（含 AI 评估卡占位），提示"提交后 4 小时内审核"。
- 提交后跳转"我的商品"，状态为待审核，可查看排队位次。
- **预检**按钮常驻在提交前，点后 30s 出建议等级，若与自述差距大，建议调整后再提交。

**审核工作台（核心）**

- 三栏布局，中间图片区占最大空间；键盘 `←/→` 切图，`A` 通过，`R` 驳回，`E` 改级。
- AI 评估卡用色块显示差异等级：绿/黄/红/蓝/灰，红标时"驳回"按钮高亮为默认焦点。
- 驳回弹窗：原因枚举（多选）+ 补充说明（≥10 字），提供常用话术模板一键填入。
- 审核完成后自动加载下一条，无需返回列表；顶部显示"今日已审 32 条 / 待审 15 条"。
- 空闲 30 秒无操作提示"是否暂停接单"（避免占用队列）。

**商品详情页（买家）**

- 图片区左大图 + 右缩略图；Tab 切换"实拍图 / AI 标注图"，标注图上缺陷类别用色块图例。
- AI 评估卡置于价格下方，视觉上比卖家描述更醒目（信任前置）。
- 右下角悬浮"下单"按钮，滚动时固定。

**行情中心**

- 顶部筛选（品种/产区/规格/等级/时间）；主图折线（成交价）+ 面积（成交量）。
- 每个图表下方"数据说明"：样本量、统计口径、更新时间；样本 <5 时显示"样本不足"。
- 无成交数据时自动回退展示"参考行情"，并标注来源。

**智能问答**

- 悬浮球在右下，点击展开侧边抽屉（不跳页，保留浏览上下文）。
- 商品页提问自动拼装上下文（"这个商品"→ product_id）。
- 流式输出 + 阶段指示（检索资料/查询行情/生成回答）。
- 引用角标 hover 显示卡片，点击打开原文抽屉。

### 11.5 前端非功能

- 首屏 JS ≤ 900KB（gzip）；路由懒加载；ECharts 按需引入。
- 兼容 Chrome/Edge 100+；交易端适配 ≥375px；后台 ≥1280px。
- 金额 `¥` 千分位两位小数；价格涨跌**涨红跌绿**（中国习惯）。
- 所有失败必须有可见反馈；表单离开前提示未保存。
- 图片懒加载 + 缩略图（列表用 300px 宽缩略图，详情才加载原图）。

### 12.5 安全与合规

| 类别 | 要求 |
|---|---|
| 传输 | 全站 HTTPS（TLS 1.2+） |
| 认证 | bcrypt(cost=12)；登录失败 5 次锁定；JWT 密钥走环境变量 |
| 授权 | 接口级权限点 + **行级强制过滤**（卖家只能操作自有商品/订单；买家只能看自己订单） |
| 注入 | 全量参数化；Agent 禁自由 SQL；排序字段白名单 |
| XSS | 商品描述与聊天内容渲染禁用原始 HTML；引用片段转义 |
| 上传 | 扩展名 + MIME 双校验；重命名 UUID；目录不可执行；单文件 ≤10MB；图片二次编码（去 EXIF 恶意载荷） |
| 盗图 | pHash 比对在架图库，命中拒绝并记违规 |
| 提示词注入 | 系统提示与用户输入隔离；注入特征检测；工具参数二次校验（防越权查他人数据）；模型输出不参与 SQL 拼接 |
| 数据脱敏 | 手机号、收货地址在列表页脱敏；日志不含明文 |
| 个人信息 | 遵循《个人信息保护法》：明示告知、最小必要、可导出与删除；对话保留 180 天后匿名化 |
| 交易合规 | 平台仅提供信息服务，不代收货款；商品页明示"平台不承担质量担保责任，争议按平台规则处理" |
| 模型合规 | 仅调用境内已备案模型服务；不向境外传输数据 |
