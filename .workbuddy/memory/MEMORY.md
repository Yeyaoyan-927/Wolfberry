# Wolfberry 项目长期记忆

## 项目定位（v4.0 定稿，前 3 版方向错误）
**枸杞交易平台**（B2B/B2C 撮合电商），**不是质检工具**。
- 三方：买家 / 卖家（入驻，自行上传商品）/ 平台（审核）
- 核心链路：卖家发布（上传实拍图 3~8 张）→ AI 图像评估 → 审核员审核 → 上架 → 买家下单 → 卖家发货 → 收货
- **AI 图像评估的真正定位：审核依据 + 防"图文不符"**，不是产品卖点本身
- 商品页展示"平台 AI 外观评估卡"；评估快照永久保留作纠纷举证
- 支付线下（只登记状态与凭证）；物流只记公司+单号
- 行情基于平台成交数据聚合（冷启动靠人工录入参考行情）

## 方向纠偏史（避免重犯）
| 版本 | 错误理解 |
|---|---|
| v1.0 | 交易平台方向对，但把"检测"错做成知识问答 |
| v2.0 | 做成收购点光谱筛查工具，偏离电商 |
| v3.0 | 做成单机质检工具，仍不是买卖平台 |
| v4.0 | 正确：交易平台 + 图像评估作审核手段 |

## 核心机制：等级差异标记（产品灵魂）
卖家自述等级 vs AI 建议等级：一致=绿；高报1级=黄；高报≥2级=红（默认建议驳回）；低报=蓝；AI 置信<0.45=灰（不参与判定）。
同一卖家 30 天红标≥3 次 → 账号预警。

## 技术栈
Vue3 + JavaScript + Element Plus + ECharts / Python + FastAPI + MySQL 8 / RAG + Agent + LangChain + LangGraph
图像评估：YOLOv8n/s-seg → ONNX，CPU 可跑（无独显也能用）

## 架构底线
1. AI 只给建议，最终等级由审核员确认并留痕（不可由 AI 直接上架）
2. LLM 不参与等级判定与价格计算，等级映射/价格/校验全走规则
3. 已上架商品改图或改级 → 强制重新审核（防换图）
4. 审核记录、AI 评估、订单、售后**不可删除**；评估快照含 model_version + threshold_version
5. AI 评估不可用不阻塞交易（人工先审，评估异步补写，标注"评估中"）
6. 多图汇总：先合并计数再算比率，禁对比率取平均；类别互斥 霉变>坏果>油果>杂质>正常
7. 霉变率 >1.5% 一票否决（等外，不许上架）
8. 只做外观，不给硫/水分/多糖/农残数值
