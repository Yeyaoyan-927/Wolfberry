6. 问答左栏半屏粉色渐变（`.side` 用了 linear-gradient 到 brand-soft）

### 二、RAG 切分（原实现只有一条固定路径）
- 策略：clause / md(新) / recursive / qa + auto 探测
- **短块合并**（关键）：同父级或无层级文档的短块合并到块长上限。原条款式文档切出 8~40 字碎片（embedding 信息量不足，命中但答不出）
- 分组键 `_group_key`：有章节链用父级，无层级统一 `__flat__`；**内部分组键绝不能写进 context/section_path**（踩过：`__flat__` 泄漏到用户可见字段）
- 新增接口：`POST /kb/preview`（试切分+质量报告）、`POST /kb/documents/{id}/rechunk`、`DELETE /kb/documents/{id}`
- 切分参数 size/overlap 持久化到 `kb_document`（`migrate_db.py` 幂等 ALTER）
- `scripts/rechunk_all.py`：批量体检（平均<80字或过短>30% 判碎片化）+ 重切
- **实测**：4 篇文档 3 篇碎片化（过短块 100%）→ 重切后 15片/35字 → 2片/270字；Recall@5=1.0，MRR 1.0→0.906（块变大，精确性略降，答案更完整）

### 三、Agent 流程过程
- `POST /kb/ask/stream`（SSE）：start → step(running/done+耗时+摘要) → done/error
- `runner.stream_agent` 用同一张图的 `astream`，与同步 `invoke` 结果一致
- 前端 fetch+ReadableStream（axios 会整体缓冲），渲染「执行过程」卡片：转圈/对勾、耗时、工具明细、可折叠
- 实测 8 事件 / 3 节点完成 / market 意图 2 工具

### 关键教训
- **低分辨率截图会误判**：曾以为步骤条显示 ①③③、预览等级不同步，2x 截图证实都是 ① ② ③ 且同步正确。像素级结论必须高清截图
- **dump-dom 早于异步渲染**：SPA 动态 import 未 resolve 时 `#app` 是 `<!---->`，不能据此判断页面空白；用截图或探针读 getBoundingClientRect
- Chroma 多进程：脚本进程写完后，运行中的服务需重启才能稳定读到新切片

## 清理无图商品 + 售后工单模块（commit 422d9f6，已推 Gitee）

### 一、无图商品清理
- `scripts/clean_image_products.py`（默认只读，`--fix` 执行）判定三类：无 product_image / 原图文件缺失或 0 字节 / 全部被 L1 拦截
- **删除规则遵守架构底线**：有订单 → 只下架不删（订单是交易凭证）；无订单 → 删评估→删图→删商品
- **关键修复**：`/admin/audit/logs` 原来是 `inner join Product`，商品删除后审核记录查不出来 = 变相抹掉留痕，且 `total`（不含 join）与实际行数不一致导致分页错乱 → 改 `outerjoin` + `coalesce(title,'（商品已删除）')`
- 实删：#4 审核演示·驳回用例、#6 中宁红枸杞（均无图无订单），删前 JSON 备份到 `backend/var/backup/`
- 清理后：4 件商品全部有封面，6 张图全部 HTTP 200

### 二、售后工单
- 表 `after_sale` + `after_sale_log`（轨迹只增不改）
- 状态机 `domain/after_sale_state.py`：1待响应→2同意/3拒绝→4平台介入→5已解决/6关闭，单向；apply 仅限订单 status 3/4，同订单不可重复提未结案单
- 卖家「同意」即结案（平台不接支付，退款线下执行，只记金额与结论）
- 接口：`POST /orders/{id}/after-sale`、`GET /after-sales`（按角色隔离）、详情、`respond`、`escalate`、`POST /admin/after-sales/{id}/resolve`、`GET /admin/after-sales/stats`
- 前端：交易端「售后服务」（工单卡片+筛选+详情抽屉+按角色操作）、订单页「申请售后」（类型/说明/金额/举证图）、管理端「售后仲裁」（左树右表+裁决弹层）
- 新增通用上传 `POST /uploads?scene=`：售后举证落 `after-sale/evidence/`，与商品图（触发 L1+AI 评估）分离；scene 白名单 + 10MB + 仅登录

### 踩坑
1. **`resolve` 忘记登记状态流转**：TRANSITIONS 缺 `(AS_ESCALATED, ACT_RESOLVE)` → 500，补占位并用 outcome 覆盖目标态
2. 用户 id 映射记错（admin=1 / seller1=2 / seller2=3 / buyer1=4），测试脚本按 seller_id 选卖家时写错导致 403
3. 前端 API 层重复插入 `uploadImage` / `const route = useRoute()` 导致构建报 "already declared"，替换脚本要检查唯一性

### 验证
- 售后全流程 19 项、通用上传 5 项、全量接口回归 22/22
- 已知：管理端售后详情深链（?ticket=）在 headless 环境未生效，点击表格行正常（同模式在知识库切片已验证）；功能主路径不受影响

## 评价 + 资质 + 注册 + 买卖边界（commit 897050b）

### 端口变更（用户指定）
- 后端 8000 → **8009**，前端 5173 → **5176**（vite proxy 同步）。注意：8000 曾被一个非本项目进程占用，响应格式不同，排查时先确认端口归属。

### 一、商品评价
- 表 `product_review`（order_id 唯一）+ `product.rating_avg/review_count` 冗余
- **边界规则**：仅已完成订单可评；有未结案售后时不可评（`AS_OPEN_STATUSES`），售后结案后可评
- `with_images` 统计踩坑：`images` 存 `[]` 时 `isnot(None)` 也为真 → 必须用 `func.json_length(...) > 0`
- 列表排序 `rating_desc`：`[review_count == 0, rating_avg.desc(), review_count.desc()]`（无评价排后）

### 二、卖家资质
- 表 `seller_qualification` + `sys_user.seller_status`（0未提交/1待审/2已认证/3驳回）
- 发布商品硬校验 `seller_status == SQ_VERIFIED`；`SellerUser` 去掉了 admin
- **数据一致性坑**：迁移只改了 `sys_user.seller_status` 没建资质记录 → 后端放行、前端显示"未认证"。`mine()` 改为无记录时以状态位兜底，并补查经营数据（否则显示 0 件商品）

### 三、注册
- `POST /auth/register`：buyer/seller 二选一，卖家必填企业名，不开放 admin 自助注册，注册即登录
- 前端登录页内嵌注册（`?mode=register` 深链）

### 四、边界收敛（4 处修正）
1. 管理员从卖家白名单移除（原来能发布商品、出现在审核队列）
2. 详情页下单区按角色渲染（原来卖家点了才弹提示）
3. 订单页标题/操作按角色区分（我的订单 vs 我收到的订单）
4. 卖家菜单仅 role=seller 可见，未认证时"资质认证"带红点

### 重复替换事故（反复出现，需警惕）
本轮多次因 `str.replace` 命中两处导致：`uploadImage` 重复导出、`const route = useRoute()` 重复声明、`el-alert` 块重复、`useAuthStore` 重复 import。
**教训**：批量替换后必须 grep 计数校验（`grep -c`），构建报 "already declared" 基本都是这个。
